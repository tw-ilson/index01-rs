# index01-rs

Talk to an Index 01 ring directly from Linux over BLE (btleplug/BlueZ). No phone app or account is needed.

## One-time setup (required for recording)

The ring ignores the record button unless the PC sent its identity key (IRK) when pairing. BlueZ only does that with privacy enabled:

```sh
# /etc/bluetooth/main.conf, [General] section
Privacy = device
```

```sh
sudo systemctl restart bluetooth
bluetoothctl remove AA:BB:CC:DD:EE:FF   # drop any old bond
bluetoothctl                            # then: scan on → pair <addr> → trust <addr>
```

Tap the ring to wake it before pairing. Pairing is Just Works, so there's no passkey. If the ring was paired before privacy was on, it bonds and transfers fine, but button presses do nothing. Re-pair it. See `../PROTOCOL.md`, "Recording requires the central to distribute its IRK".

## First-time setup of the ring

A ring that has never been set up (no user record) needs one write. This is what the phone app does on first setup:

```sh
index01 setup <addr> --yes [--user-id NAME]   # writes the user record + sets the clock; refuses if one exists
```

## Usage

The ring sleeps after about 3 minutes idle. Tap it to wake it before each command.

```sh
index01 scan
index01 info  <addr>
index01 list  <addr>
index01 pull  <addr> --out recordings   # collection_N.bin + recording_N.wav per recording
index01 decode recordings               # rebuild recording_N.wav from saved .bin files, offline
index01 set-time <addr>                 # set the ring clock (it resets when the ring wakes from sleep)
index01 erase <addr> --yes --out recordings  # delete stored collections; refused unless all were pulled into --out
```

To record, press the button and speak; the ring flashes twice when it's done. A recording is split across several collections of about 4 KB each. `pull` and `decode` join them into one WAV per recording.

## Provenance and tests

This is a clean-room-style port. The protocol, the collection format, the audio codec and the user-record format were recovered by reverse-engineering the vendor's Android library and the ring firmware. Functions in `src/haversine/` cite the library function or address they replicate.

The JSON test vectors in `tests/` were generated by running the original closed library. The `gen_*.py` scripts that produced them need that library, which is not included, so they can't be re-run from this repo. `cargo test` only needs the committed JSON.
